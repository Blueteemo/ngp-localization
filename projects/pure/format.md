# Pure 已确认的格式与边界

本文件只描述指定日版 SHA-256。文件偏移与 CPU 地址要区分：ROM 起始映射为 `0x200000`。

## 文字执行

| 项目 | 已确认位置或行为 |
| --- | --- |
| 文字读取入口 | CPU `0x201A18` |
| 字体绘制入口 | CPU `0x201BFD` |
| 原字体基址载入 | 文件 `0x1C0A`，原基址 CPU `0x210000` |
| 原字库 | 文件 `0x10000–0x1FFFF`，P05 不修改 |
| 当前文本指针 | RAM `0x4256` |
| `FE` 正文入口 | CPU `0x2009EA` 起，另保存入口至 `0x42A8`，重置位置等状态 |
| `FD` 系统文本入口 | CPU `0x200A33` 起，不完全等同正文 |
| 脚本绝对跳转 | opcode `02` + 三字节 CPU 地址 |

P05 将原 `FD` 文本重定向到新记录，结束后跳回原记录末端。保留原等待、清屏与速度信息。
**目前正文 `FE` 的完整迁移尚未实现**，尤其要研究它对进度位置与存读档的影响。

常用文本控制：`80` 结束，`81` 换行，`82` 等待输入，`83` 清屏，`84/85` 速度模式，
`87` 后跟两个定位参数，`88` 动态数字，`8A/8B` 光标微调，`8C` 后跟速度参数。
`C0..FF` 的字页行为须结合文本语境；估算器拒绝可疑嵌套入口，不把字节匹配当成完整语法分析。

## 字形

12×12，一字 18 字节，1bpp 源位图，按 4 像素 nibble 对交错存储。
格式以 `ngp_localization/glyph12.py` 和单像素已知映射测试为准。

P05 私有字形以页 48 起编码，一页 128 槽。字体选择由**新文本地址上下文及页范围**限制，
不能全局覆盖原字体，否则未汉化正文会错字。私有基址补偿与原绘制例程的算术有关，
不能随意换字页、扩大 glyph 数量而不检查算术和地址边界。

## P05 区域布局

| 文件范围/起点 | 用途 |
| --- | --- |
| `0xD0000` 起 | 重定位文本与图像状态卡，结束必须早于 `0xD3000` |
| `0xD3000` 起 | 318 枚私有字形，结束早于 `0xD4800` |
| `0xD4800` | 字体选择钩子 |
| `0xD4900` | 菜单就绪派发包装 |
| `0xD5000` | 克隆的标题资源 |
| `0xD8000` | 署名绘制例程 |
| `0xE0000` 至 ROM 末端 | 保持原样；不能仅以零/FF 分布推断可用空间 |

字库区不是全文扩充空间。将来需要规划新的布局、寻址和可能的扩容，并重新验证保存区。

## 图像资源

资源表：文件 `0x3576 + resource_id*4`，内容为四字节 CPU 指针。
加载器相关入口：CPU `0x202640/0x2026A7`。

资源记录含背景色、32 组滚动层和 16 组精灵调色板、宽高、交错的双平面 tilemap、
精灵列表、tile 数量及 16 字节 2bpp tiles。调色板 `0x8000` 为短记录哨兵。
具体读取和保护断言在两个资源生成脚本中。

- 100：标题。P05 复用原提示字的 tile 槽，保持原记录长度和 tile 总数，保留原圈 A 像素。
- 101/102/103：保存、初始化、开始菜单三张卡。只改文字 ROI `[12,16,60,72]`。

## 署名时机

菜单会预绘制文字再滑入。P05 不在字体钩子中绘制署名。
它包装 opcode `0x20` 的派发表入口，最终仍跳回原处理函数 `0x2014AC`。
仅当脚本参数指针为 `0x2912D7` 且当前文本为已完成标题记录时绘制。

署名位于 y=75，10px，灰色 `0x555`，使用 VRAM tile 352..371 和滚动层调色板 3。
这些槽位由原场景验证选出；文字缓冲会使用 404 之后的区域，因此不能改用 480..499。
