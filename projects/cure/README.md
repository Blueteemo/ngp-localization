# 《无限轮回：Cure.》经验案例

该项目已形成可直接启动的简体中文 ROM 定稿。**本仓库首版目前没有迁入它的完整正文重建工程**，
不能凭这里的文档声称能独立重建 Cure。后续应逐项整理，而不是一次上传含游戏数据的历史包。

历史冻结输出为 2,097,152 字节，SHA-256：

```text
515cbab5326299e5f5f0db7bc29d8d47ba689b1bf52f029c03fa9d8b2456a31e
```

## 已有工程经验

- 正文翻译、字库扩充与大量文本重定位，保留选项、分页和分支控制。
- 菜单汉化及居中、按 A 提示、署名；中文 LOGO 试稿最终未采用。
- 像素字形反复比较，“汉”字最终保留批准的 C 方案；不能为了连笔随意增加像素。
- 新建存档、跨进程读取、取消/确认覆盖、取消初始化，分别验证保存数据与代码/字体区域。
- 开场音乐与动画在不同模拟器和 RG35XX 上有不同表现，实测现象需要与推断分开。
- 冻结定稿与可复现重建，保留已知模拟器兼容性问题及人工审校队列。

历史最终记录中的静态检查覆盖 17,150 条正文集成、5,847 条重定位、162 处分支与 78 个全局选项。
这证明结构检查范围，**不等同全路线自然通关或全部人工终校**。

## 对 Pure 的直接帮助

十个已经选好的 Fusion 菜单字形被保留为 OFL 子集；动态追踪、字库上下文限定、
重定位与存读档验证的做法也能复用。但 Pure 的地址、具体资源结构和正文入口仍须独立验证。

## 后续迁入边界

优先迁入通用的脚本、脱敏后的格式说明、字体授权及可公开的自制示例。
历史归档中的整 ROM、游戏资源、完整译文表、私人存档或云盘标识不随包上传。
