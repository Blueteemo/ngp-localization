# 验证的层级

| 检查 | 能说明什么 | 不能替代什么 |
| --- | --- | --- |
| 构建哈希一致 | 生成同一个冻结 ROM | 游戏实际显示和可操作性 |
| 文本指针/节点到达 | 执行流走到该入口 | 文字真正可见、没有缺笔 |
| 实际截图 | 某一帧的版面 | 切换动画全过程 |
| 连续逐帧记录 | 动画期间何时出现/消失 | 全剧情全部分支 |
| 跨进程存档读回 | 持久化恢复到预期位置 | 所有存档位置、所有核心 |
| 双核心对照 | 暴露实现差异 | 原硬件验收 |

`projects/pure/reference/p05_observations.json` 是历史工程观测，不是本仓库的一次陌生 Agent 验收结果。
构建适配迁移后会在 README / 状态中记录实际执行的检查，不把尚未执行的入口算作通过。

## Pure 场景

- 开场：各运行 17,500 帧，三轮自然循环覆盖 14 字段，比较各自原版的 24 个节点。
- 菜单：18 个功能画面，输出原始截图。
- 存档：先结束菜单测试进程，再开启进程读回；比较脚本位置，并继续推进一页。
- 初始化：只对测试存档的复制件操作，再重启查看空槽。
- 署名：标题 → 菜单 → 设置 → 标题 → 菜单，检查出现与消失。
- 转场：逐帧读取原菜单状态与灰色像素数，要求转场前为 0，就绪后出现。

Native 的 `validate` 会同时报告黑底叙述可见性。若为 false，应保留已知失败，使用 Med 的画面作为
当前可见性验证来源，继续研究模拟器差异时另建任务。

## 有声录制

先运行 Med 开场验证生成标题参考图，再运行 `record`。从冷启动开始，不载入即时存档，
自然播放完整一轮开场，检测标题完整显示，稍作停留后实际按 A，最后停留在菜单。

记录：ROM 哈希、核心、帧数、采样率、声道、音频样本数、按键帧号、输出哈希。
检查黑底叙述确实可见，并检查音画总时长、音频峰值及截断。演示为模拟器运行，不能称为实体掌机录像。

视频开头约 0.03 秒边缘的剪裁是演示编辑事项，不修改定稿 ROM。
